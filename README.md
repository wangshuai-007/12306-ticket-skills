# 12306 购票执行技能

让支持 Skill 的 AI 通过浏览器实际协助购票和计次票预约，而不只是提供操作教程。

## 支持的任务

- 使用已购计次票预约具体车次、切换往返方向、查看预约记录。
- 购买计次票产品，并在购买成功后继续预约席位。
- 查询和购买普通车票，核对行程、价格及出票状态。
- 按用户授权取消或调整计次票预约。
- 有实际 APP 控制工具时，协助操作“铁路12306”APP。

**技能不会保证所有行程都有票。** 只有页面及订单记录确认成功，才报告购票或预约成功。

## 安装

以 Codex 本地技能目录为例，将仓库克隆为一个技能文件夹：

```sh
git clone https://github.com/wangshuai-007/12306-ticket-skills.git "$HOME/.codex/skills/12306-ticket-rules"
```

仓库根目录就是技能根目录，不需要再套一层文件夹。已存在同名目录时不要重复克隆或覆盖。

更新已克隆的版本：

```sh
git -C "$HOME/.codex/skills/12306-ticket-rules" pull --ff-only
```

其他 AI 环境按其技能加载方式，将包含 `SKILL.md` 的整个目录加入技能目录。

## 使用

在能够加载该技能、且具备浏览器控制能力的会话中调用：

```text
$12306-ticket-rules
用我的计次票预约本周五南京南到滁州，18:00之后最早一班，有座优先。
```

也可以指定日期和车次，或要求购买普通车票。请提供具体发到站、日期、班次或可接受时间范围、乘车人；需要付款的购买任务还应提供价格上限或确认实际报价。

AI 会读取当前页面，核对产品及行程，完成已授权的操作，并核验订单状态。登录或付款需要你配合时，完成后可在同一会话继续。

## 默认行为

- **有座优先**：不默认预约无座；符合日期、方向、班次范围、产品和预算的有座选项全部不可用时，才使用无座。明确要求不接受无座时不会使用。
- **计次票席别**：沿用已购产品席别，不重复追问已经能从产品确定的信息。
- **账号登录**：默认账号密码 → 绑定证件号后四位 → 短信验证码，不主动要求扫码。网站存在扫码入口不改变这个默认选择。
- **敏感信息**：账号密码、证件信息及验证码直接在官方页面填写，不发送给 AI，不写入技能文件。
- **浏览器兼容**：优先 Chrome DevTools MCP；没有它时使用当前已有的浏览器工具，不强制安装特定工具。
- **不重复提交**：提交超时先检查订单或预约记录，不直接再次下单。
- **不擅自改行程**：不超出用户日期、站点、班次范围或预算，也不自行取消已有预约。

## 成功标准与使用边界

普通票须核验支付及出票成功；计次票产品须确认到账；计次预约须确认对应行程在待出行订单中显示“已预约”，并核对实际席位。
待支付、候补已提交、系统处理中都不等于已购到票。

技能本身不提供浏览器、登录账号、余票或支付能力。运行环境必须有可用控制工具，敏感交接及最终支付遵守该环境的权限要求。
仅有浏览器工具时不能控制原生 APP；用户同意后可改用网页。
用户只问规则或方法时不会创建订单；修改技能或演示流程也不等于授权真实购买。

## 已验证范围

2026-10-12 已使用 Chrome DevTools MCP 完成真实计次票预约：
登录恢复 → 全部产品订单 → 预约查询 → 日期及方向选择 → 约号确认 → 提交 → 成功页 → 待出行“已预约”记录及席位核验。

普通票完整出票、新产品支付、取消预约及 APP 实机操作尚未完成端到端实测，不将这些流程表述为已验证成功。
页面、产品条款和余票可能变化，每次执行均需读取当前状态。
