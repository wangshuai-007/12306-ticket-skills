# 浏览器执行约定

## 工具发现与连接
先发现当前工具。Chrome DevTools MCP可用时按以下能力执行；不可用时用当前浏览器工具的页面列表、快照、定位、填写和点击等对应能力，业务流程与成功标准不变。
不要因为当前工具名不同就宣布技能不可用、要求切换环境或先问用户是否安装Chrome工具；只在没有任何可用浏览器控制能力时说明阻塞。
通过宿主工具发现机制查找以下能力；本环境可通过ALL_TOOLS找到完整名称和参数。
- list_pages：读取可用标签页。优先已有12306任务页，不覆盖用户其他页面。
- select_page：选择目标页；用户要看到操作时可bringToFront。
- new_page / navigate_page：打开官方页面。无官方页才新建；多个任务页按URL和当前状态确认目标。
- take_snapshot：获取可访问性树和元素uid；所有操作使用最近一次快照的uid。
- click、fill、fill_form、press_key：实际操作控件；fill用于文本框或下拉框。
- wait_for：等待具体成功文本或结果区域，不用固定长延迟代替状态读取。
- take_screenshot：快照无法判断控件时辅助查看；只截必要区域，避免泄露证件或付款信息。
完整名称示例：mcp__chrome_devtools__list_pages、mcp__chrome_devtools__take_snapshot。
不同宿主前缀可能不同，应以实际发现结果为准，不能只因为名字不同就停下。

## 页面循环
1. take_snapshot，确认当前页面与任务状态。
2. 从当前快照定位目标uid；填写或点击一个有明确结果的操作。
3. 页面跳转后list_pages检查是否新开标签；必要时select_page。
4. take_snapshot检查变化；异步加载时wait_for页面实际预期文本，再读取快照。
5. 成功则进入下一步，错误则解释并处理；无变化时重新定位原因，不能盲目重复点击。

## 车站和日期输入
- 车站框常有联想列表：fill站名后读新快照，选中用户指定的具体车站，确认控件显示已选车站。
- 不只输入汉字就认定底层站点已选；不得用evaluate_script修改隐藏站点代码绕过选择。
- 日期按控件格式输入或使用日历；核对查询结果的日期，不把页面默认今天当成用户日期。
- 回程先核对方向切换后的实际发到站，再查询。
- 结果列表可能有同城市多个站、跨日到达和不同票价，按完整行程匹配，不按第一条结果默认预订。

## 页面读取边界
优先用快照uid操作。必要时evaluate_script读取当前DOM中已呈现的文本、标签或表格结构。方向切换等可见控件缺少唯一uid时，允许对已观察并确认可见的唯一DOM控件调用click；随后读状态核验。不得用此方式绕过授权或改隐藏字段。
不调用隐藏购票API，不注入自动抢票，不读取Cookie、token、localStorage、密码字段或全量个人资料。
默认不读取网络请求；购票成功以页面和订单记录核验，不把HTTP200作为成功。
无授权不高频刷新。服务繁忙时短暂等待后检查状态；同一失败重复两次后改变诊断或说明阻塞，不无限重试。

## 登录与付款交接
- 默认请用户在官方页面完成：账号密码 → 点击“立即登录” → 验证弹窗输入绑定证件号后四位 → 获取短信验证码 → 输入验证码并点“确定”。不主动询问是否扫码，也不要求用APP扫码一次以复用登录态。
- 页面可能提供扫码入口，但不作为默认流程；不把本技能的默认选择表述为网站永久没有扫码功能。用户主动要求扫码时可按当前页面处理。
- 用户说“已输入账号密码”不代表登录成功；只读检查是否出现短信验证弹窗，出现则请用户继续上述验证，不重复索取账号密码。
- 登录页可能含已输入密码或手机号，尽量只读取页面标题、验证提示和登录状态，不检查密码框值；快照返回敏感字段时先遮蔽再输出，不写入技能或记录。
- 用户登录后无需重新询问能否继续已授权的查询；读当前页面恢复。
- 登录过期：保留任务行程，用官方页面请用户重新登录；不得反复尝试凭据。
- 付款：明确订单已提交但未出票，请用户在官方页面完成付款；以宿主确认规定为准。
- 用户反馈“已支付”：刷新或重新打开订单详情核验状态，不能只凭口头反馈宣称出票。
- 若需下一轮继续，只在会话上下文保留必要行程和脱敏任务状态；不写敏感会话数据到技能文件。

## APP分支
有真实APP控制工具时采用同样的观察—操作—核验循环，并读取当前APP控件。
只有浏览器工具时不能操作原生APP；手机网页也不等于APP。
用户同意切换网页后执行网页流程；不同意则明确工具能力阻塞，而不是宣称已完成。
