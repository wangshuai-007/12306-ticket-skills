# 实际购票流程

本文服务于执行，不是要求用户自行完成全流程。页面名称为业务提示，按钮必须从当前页面定位。
区分普通票订单、计次产品订单、计次预约记录；先确认当前操作目标。

## A. 使用已购计次票预约（优先）
1. 登录后从个人中心“订单中心 → 计次•定期票订单 → 全部订单”读取已购产品。默认“待支付订单”为空不能判断无产品。完整已验证路径见 [网页实测](web-verified-flow.md)。
2. 找到正确乘车人的产品，核对固定区间、席别、状态、启用期限及剩余次数。
3. 点击所选产品行的“立即预约”，核对乘车人弹窗，点击“去预约”进入查询页；这一步尚未提交车次预约。APP公开指南曾有“去使用”，以当前界面为准。
4. 根据用户方向设置发到站或切换方向；选择日期，查询该产品的可预约班次。
5. 匹配车次或用户给出的时间范围，核对方向、具体车站、日期、时间及可预约状态。席别未指定时沿用产品席别且优先有座，不重复询问已能确定的席别。检查允许范围内所有有座选项；全部不可用才预约无座，用户禁止无座时不使用。同班车“二等座”和“无座”分别有同名“立即预约”，必须按席别定位按钮，不把无座余票当作有座余票。
6. 提交前执行 [重复行程检查](duplicate-itineraries.md)，同时查普通票和计次预约。已有同日同起止站车票时列出重复信息并确认继续；之后核对“约号确认”并点“确认约号”，只提交一次。若跳出额外普通票付款页，先检查是否走错入口。
7. 等待“预约已成功”并读取实际座位；点“查询订单详情”进入“约号订单 → 待出行”，确认目标记录“已预约”。文本等待超时先检查当前页面和记录，不直接重提。重复行程成立时按参考设置最早发车时的再次提醒，并核验调度结果。
8. 失败时按下方异常分支处理，不因为有产品或点击过按钮就认定已预约。

## B. 首次购买计次票产品
1. 进入产品购买功能，选择用户要求的支持线路/固定站间组合及计次产品，不混选定期票。
2. 选择乘车人、席别，读取产品总价、次数、启用期限、有效期与当前条款。
3. 比较用户价格上限及使用需求。已有同类产品时先核对是否用户实际要预约，不重复买。
4. 授权与信息齐全后提交购买订单；协议、验证码与付款按宿主规定交接。
5. 用户付款完成后查看已购产品，核对到账、乘车人、站间、席别、次数及状态。
6. 用户还要求某班车时继续A流程；否则报告产品购买成功，不声称已有对应班次车票。

## C. 普通车票（仅执行必要步骤）
1. 进入官网首页或普通票查询页，选择具体出发站、到达站、日期，查询。
2. 读取车次、发到站、发到时间、日期、席别、余票和实际票价，匹配用户要求和预算。
3. 选车次预订，选择指定乘车人、票种和席别；儿童、学生等仅在用户需要时处理。
4. 核对确认页实际行程、乘车人、票价及额外项目，不默认勾选保险等可选收费服务。
5. 提交前执行 [重复行程检查](duplicate-itineraries.md)，查同日同起止站的普通票和计次预约，已存在时提示并确认继续。用户授权完整且未超预算时提交；出现新价格、替代席别等变化先向用户确认。
6. 等待系统处理，查看是否生成待支付订单；交接付款并说明当前不是出票成功。
7. 用户付款后从订单详情核验已支付/出票状态及具体席位。订单未完成就继续处理，不用教程替代结果。重复行程实际成立后设置最早一趟发车时的再次提醒，不能把尚未付款的订单当成已购票。
8. 优先用户指定席别或预算内可选有座席别；未指定时不先选无座。所有符合已授权行程与预算的有座选项均不可用后，才按默认策略使用无座；用户明确禁止无座时不使用。不擅自换日期、站点、班次范围或超预算升级；需要改变这些条件时询问唯一必要选择。

## D. 调整或取消计次预约
1. 进入所选产品的预约记录，匹配用户要求的日期、方向和车次。
2. 单纯取消：有明确取消授权后操作，并确认对应记录已取消。
3. 改班次：先读取是否有正式调整功能；按当前页面处理。
4. 只有取消重约时先查目标班次并说明席位不保证；没有取消授权不能先取消旧预约。
5. 核验新预约及旧预约状态，防止把两条预约均有效或新预约失败报告成改签成功；重复行程消失或最早发车时间变化时，同步取消或更新该组提醒，不修改无关提醒。

## 异常分支
| 观察到的状态 | 实际动作 |
| --- | --- |
| 未登录或登录失效 | 让用户在官方界面登录；保留行程，登录后恢复当前流程。 |
| 无对应产品 | 确认当前账号和乘车人；用户原本只要求预约时不自行购买产品。 |
| 产品失效、次数不足或尚未满足启用条件 | 读取产品状态与说明，解释具体阻塞；另买票或产品需授权。 |
| 待用预约数量达到上限 | 读取现有预约；不能擅自取消腾名额，问用户是否取消指定行程。 |
| 无余席但有候补入口 | 用户已授权候补才提交，否则确认候补或其他班次；候补不算出票。 |
| 候补容量或入口与历史经验不同 | 采用当前页面，不保证额外固定名额。 |
| 系统繁忙、提交超时、断线 | 先查产品预约记录或订单，确认是否已生成；查明未成功后才重试。 |
| 有待支付订单 | 恢复该订单，核对是否目标行程及剩余支付时间；不重复下单。 |
| 行程/乘车人/席别匹配错误 | 提交前修正；已提交时先说明状态，不擅自取消或退款。 |
| 身份核验、验证码或协议阻塞 | 交接必要步骤，不规避校验，完成后重新读取状态。 |

## APP操作
用户明确要求APP且有控制工具：从首页“计次·定期票”的当前入口执行A/B/D。
普通票从首页查询执行C；入口位置与名称以当前版本为准。
没有APP控制工具时使用浏览器需征得平台切换同意，不用网页模拟APP宣称实际操作。

## 刷证与成功定义
直接刷证是现场使用产品的方式，不是远程预约；助手不能替用户现场检票。
可解释作者实测和适用条件，但不能用“到站刷证即可”代替用户要求的席位预约，也不能远程保证有座。
官方公开入口及规则来源见浏览器执行约定与京沪规则参考；登录后页面运行时核验。
