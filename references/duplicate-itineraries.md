# 重复行程检查与首趟发车提醒

这是用户要求的购票防误操作规则，不是铁路禁止购买同向多张车票的规定。适用于普通票和计次票预约，不禁止有意购买多趟。

## 判定口径
- 按票面出发日期、具体出发站、具体到达站分组；相同站名的规范写法可归一化，不将不同车站仅因同城合并。
- 方向有序：A到B与B到A不是同向重复；使用出发日期，不使用下单日期或到达日期。
- 已出票普通票与已成功计次预约合并比较，覆盖同日待出行及已乘记录；购买计次票产品但尚未预约不算一张具体行程车票。
- 已取消、已退款及确认改签作废的旧票不计入。待支付、候补未兑现另列为未完成需求，不能计入“已购车票数量”，但要检查是否应恢复旧订单而不是重复提交。
- 同一张票在本人车票、普通订单或约号订单多处展示只计一次；用当前会话中可见的订单/票标识及乘车人、车次和时间核对去重，席位格式前导零不构成不同票。
- 必须列出乘车人以区分同人重复与多人同行；不同乘车人不能声称同一个人买了两张，但同日期同起止站的多票仍需明确提示是同行票。
- 比较范围为本次任务相关账号和订单的可见信息，不检索不相关个人资料；可见范围不足时说明检查范围，不能断言所有渠道均无重复。

## 提交前：第二次购买即提示
1. 在目标日期、发到站及乘车人已确定后，提交普通票订单或点击计次“确认约号”前，查看普通票订单和约号订单/预约详情。
2. 按上面口径去重，并将本次拟购买行程加入比较。已有1张同日同向票时，本次就是第二次；车次和时间不同也须提示，不仅检查同车次。
3. 明确列出已有票和拟购买票的日期、方向、乘车人、车次、发车时间、席别及状态，不输出完整证件、订单号或敏感链接。
4. 问是否仍要购买/预约该次行程。用户之前只说“帮我买这班”不代表已知重复；用户已明确知道重复并要求继续时不再重复确认。
5. 用户不继续则停止提交，保留已有票。用户确认继续才完成原流程；不自动取消、退票或挑一张保留。
6. 手动介入、改签、超时或重连后先核验订单是否变化，不能用过时快照再次提交。
7. 订单查询受登录或工具限制时先恢复查询；仍无法核实时明确检查未完成，请用户核对已有票并确认是否继续，不默认视为没有重复。

提示示例：
“你在10月16日已有南京南→滁州的G甲车次（18:00，有座，已预约）；本次拟预约G乙（19:00）。同一天同方向将有2张票，是否仍继续预约G乙？”
不同乘车人示例：
“同日同方向已有甲的车票，本次为乙购票，属于多人同行，不是甲的重复票；是否按同行计划继续？”
示例车次和时间只作格式说明，不是本次真实任务或实际运行时刻。

## 成功后：首趟发车时再次提示
- 仅在第二张票真实出票或预约成功后创建提醒。待支付、候补未兑现、提交失败不构成已购重复，也不虚构新增票。
- 在本组所有仍有效车票中按完整发车时间排序，取最早一趟的票面计划发车时间，而不是购买顺序第一张票的时间。
- 使用行程所在地时区；中国境内行程用Asia/Shanghai，传入完整年月日和时间。发车时间不明确时先核实，不能自行猜测。
- 若该时间已过或就是当前时间，立即再次提示，并说明首趟已到计划发车时刻；不创建过去的任务。
- 若该时间尚未来到，发现并调用宿主实际提醒/自动化工具。用户启用本规则并确认保留重复行程后，无需再问是否建立对应提醒。
- Codex环境先发现automation_update工具，优先使用当前会话的heartbeat按宿主支持的方式在目标时间唤醒；不要创建独立新会话，不手写自动化指令或靠sleep长期等待。
- 只能使用工具支持的调度精度；无法按目标时间调度时明确告知。创建返回成功、时间/时区和启用状态正确后，才说“已设置提醒”。
- 同一日期、方向和相关乘车人的重复组只保留一个首趟提醒。第三次购买或最早班次变化时，查找并更新已有匹配提醒，保留无关字段，不创建重复通知或覆盖其他任务。
- 运行时只保留必要的分组信息、行程概要和提醒标识，不把真实行程、账号或提醒任务写入本技能公共文件。
- 无调度工具、创建失败、需要权限或环境不能后台运行时，购票结果照实报告，同时明确“首趟发车提醒尚未设置”及具体原因；不能承诺会话到时自动提醒。

## 提醒触发与后续变化
1. 提醒任务只为核对和通知，不授权下单、取消、退票或改签。
2. 到时尽量重新读取相关订单状态，确认重复是否仍存在；已取消/退款后不足2张则不再发送过时的重复警告。
3. 仍存在时明确提示“首趟已到计划发车时间，同日同方向仍有多张票”，列出车次及发车时间，提醒用户核对后续行程是否需要保留。
4. 登录失效或页面不可访问时不能静默丢弃提醒：按建立提醒时的概要通知，并标注“当前订单状态未重新核验，若已取消请忽略”，不声称重复仍实时存在。
5. 购票会话内发生取消或改签时，重新计算重复组；不足2张取消该组提醒，最早时间变化则更新。其他渠道的变化尽量在触发时复核，不承诺持续实时监控。
6. 已知官方发车时间变化时更新调度；没有权威实时数据时按票面计划时间提醒，不保证实际开车瞬间准确触发。
7. 本次提示发送后将对应单次任务结束；若工具只有周期任务，按宿主支持的停止/暂停方式防止以后重复通知。
8. 不暗示发车时仍一定能免费退票；是否可退改按当时规则及页面处理，用户未授权不进行操作。

## 静态验收场景
| 场景 | 应有行为 |
| --- | --- |
| 相同日期方向已有普通票，再预约不同车次计次票 | 提交前提示；确认并成功后安排最早发车提醒。 |
| 新票比已有票发车更早 | 提醒时间取新票发车时间，不能取先购买那张。 |
| 同一票在两个订单页面出现 | 去重为1张，不因重复展示误报。 |
| 同日期反向返程或不同日期同方向 | 不算同组重复。 |
| 旧票已取消退款，或只是未兑现候补 | 不计为第二张已购票；未完成订单单独处理。 |
| 同日期方向为另一乘车人购票 | 明确注明多人同行，不声称同人重复。 |
| 首趟已发车后再购买同日同向票 | 购买前提示，成功后立即再次提示，不安排过去时间。 |
| 无调度工具或任务创建失败 | 不说已设置提醒，保留真实购票结果并报告提醒缺失。 |
| 第三张票成功，或者取消一张后不足2张 | 更新同组已有提醒，或取消，不重复创建。 |
| 到时无法重新登录查票 | 发送带“状态未重新核验”的概要，不静默跳过。 |

验证边界：以上为规则及静态场景核对，未为测试制造真实重复订单，也未创建实际提醒；实际调度效果须在有真实重复行程的运行环境中验证。
